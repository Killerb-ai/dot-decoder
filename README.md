# 점은닉 디코더 v6.2

스캔 이미지의 미세 점을 분석해 0~7로 구성된 8자리 문건 식별코드 후보를 찾는 웹앱입니다. 기존 KR 10-1989170 기반 4행 × 2열 기본영역, 각 영역의 2행 × 4열 세부분할 구조를 유지합니다.

[웹앱 열기](https://killerb-ai.github.io/dot-decoder/) 또는 `index.html`을 브라우저에서 직접 엽니다. 서버와 외부 서비스는 필요하지 않으며 이미지 처리는 브라우저 안에서 수행합니다. 테스트용 개발 의존성은 웹앱 실행에 필요하지 않습니다.

## v6.1 통합

원격 main의 v6.1 (`4eb0263`)을 기반으로 QR 정렬, 기울기 보정, 문서별 격자 보정과 모바일 촬영을 유지했습니다. 아래 v4.9 검증은 이번 안전성 개선을 개발한 로컬 분기의 기록입니다. 통합 버전은 고해상도 QR 경로를 먼저 사용하고, 해당 경로가 지원하지 않는 문서는 개선된 희소점 경로로 분석합니다. 수동 영역 모드에서는 QR 자동 정렬을 적용하지 않습니다.

## 이번 수정

- 2026-09-15 재리뷰에서 영역 경계 중복 검출, 부분 경쟁 격자 누락, 확대 후보 좌표 불일치, QR 회전 좌표와 과도한 점수, 비동기 복사 및 업로드 복구 문제를 수정했습니다. [검증 결과와 남은 한계](REVIEW.md)를 확인하세요.
- QR 격자 보정이 허용 범위의 끝에 걸리거나 문서 밖으로 크게 벗어나면 모든 영역을 검토 대상으로 표시합니다. 약한 후보와 같은 셀 안의 경쟁 점도 점수에 반영합니다.
- 경쟁 격자를 더 엄격하게 검사하므로 이전보다 판독 점수가 낮아지거나 검토 영역이 늘어날 수 있습니다. 기존 정답 숫자·점 좌표의 회귀 성능은 유지했습니다.
- 여러 밝기 단계에서 미세점 후보를 보존하고, 최소 6개 기본영역에 걸친 공통 격자를 검증합니다. 약한 확대·축소와 기울기를 허용하는 아핀 모델을 사용합니다.
- 실제 픽셀 후보가 없는 영역은 격자 위치만으로 채우지 않습니다. 경쟁 후보가 있으면 검토 상태를 유지합니다.
- 같은 세부분할에 있다는 이유로 서로 다른 점과 표선 조각을 합산하던 처리를 제거했습니다. 특정 회색값 203을 선호하던 보정도 제거했습니다.
- 강제로 100%를 부여하던 신뢰도 계산을 제거했습니다. 미검출 영역도 전체 8개 영역의 점수 계산에 포함합니다.
- 이미지 교체, 영역 변경, 초기화 시 이전 결과와 수동 보정을 모두 폐기합니다. 진행 중인 분석과 늦게 완료된 이미지 로딩도 취소합니다.
- Web Worker에서 분석하므로 작업 중에도 초기화·이미지 교체가 가능합니다. 투명 이미지는 흰 배경으로 합성합니다.
- 확대 셀 클릭은 조회만 합니다. 실제 후보 좌표를 확인한 뒤 별도의 보정 버튼으로 반영합니다. 보정 초기화는 원래 자동 결과의 미검출 상태까지 복원합니다.
- 점을 가리던 큰 채움 표시와 확대 화면의 중심 십자선을 제거했습니다. 히트맵, 미사용 튜닝 입력, 레거시 판독 코드도 제거했습니다.

## 결과 해석

**판독 점수는 정답 확률이나 검증 정확도가 아닙니다.** 대비, 후보 간 차이, 격자 오차, 경쟁 가설을 반영하는 휴리스틱 점수입니다. 같은 이미지의 임계값별 분석은 독립적인 정답 검증이 아닙니다.

`?`는 미검출입니다. 검토 표시가 있으면 후보 확대 또는 원본의 점 위치를 확인해야 합니다. 미검출·미확인 검토 영역이 남은 코드는 복사를 차단합니다. 수동 보정은 사용자의 확인으로 별도 집계하며 자동 판독 점수를 올리지 않습니다.

자동 분석 영역은 이미지의 내용 경계를 추정한 값이지 실제 코드 삽입 영역의 보장이 아닙니다. 잘린 문서, 큰 기울기, 심한 원근 왜곡, 글자·표선과 겹친 점, 압축으로 사라진 점은 여전히 오류나 미검출을 일으킬 수 있습니다. 원본 해상도를 유지하세요.

## 실제 샘플 검증

2026-09-07 로컬 원본에 대해, 답안지의 삼각형은 **위치 주석으로만** 사용했습니다. 답안 이미지 자체를 디코딩해 정답으로 삼지 않았습니다. 후보 숫자뿐 아니라 원본의 점 좌표도 비교했습니다.

기준 버전은 커밋 `7da190a`입니다. 숫자만 비교하면 24/31에서 29/31로 개선됐습니다. sample_7의 P3는 명확한 답안 주석이 없어 집계에서 제외했으며, P2/P7은 글자와 겹친 미해결 항목입니다. sample_2의 P1은 위치가 맞아도 경쟁 가설이 있어 검토 상태를 유지합니다.

이 수치는 개발에 사용한 소규모 회귀 샘플의 결과이며 미지 문서에 대한 정확도 보장이 아닙니다. 과거 README의 `4page.png / 100%`는 정답 검증값이 아니므로 철회했습니다. 해당 원본·답안 파일은 현재 지정 경로에 없어 이번 검증에 포함하지 않았습니다.

## 테스트

Node.js에서 실제 `index.html`의 JavaScript를 직접 실행합니다. 별도의 Python 재구현 결과를 앱 검증으로 대신하지 않습니다.

```sh
npm test
npm install
npm run test:samples -- "개인 샘플 폴더"
npm run test:samples -- "개인 샘플 폴더" --pipeline=document
npm run test:variants -- "sample_2 원본 파일 경로"
npm run test:browser -- "sample_2 원본 파일 경로"
npm run test:qr -- "sample_8 원본 파일 경로"
```

기본 단위 테스트는 외부 패키지 없이 실행됩니다. 샘플·변형 테스트는 Sharp, 브라우저 테스트는 Sharp·Playwright와 설치된 Chrome을 사용합니다. 다른 브라우저 실행 파일은 `BROWSER_PATH` 환경변수로 지정합니다.

- 단위 테스트: 64개 세부분할 위치, 밝기·약한 기울기, 먼지, 누락, 빈 문서·투명 이미지·표선, 부분 경쟁 격자, 소수 경계의 점 중복, 무작위 잡음, QR 회전 좌표·약한 후보·배율 한계, 확대 후보 일치, 상태 무효화·분석 취소·비동기 복사·업로드 복구.
- 샘플 테스트: 기본값은 희소점 경로이며 `--pipeline=document`는 실제 앱의 QR 우선 자동 판독 경로를 검증합니다. 알려진 오답·미검출이 검토 없이 통과하면 실패합니다.
- 변형 테스트: sample_2 원본, 최근접 2배 확대, 밝기 +5/-12, JPEG 품질 90 재인코딩.
- 브라우저 테스트: 실제 Worker, 업로드 복구, 확대 조회와 보정 분리, 초기화, 손상 파일, 잘못된 영역, 데스크톱·모바일 화면, QR 보정 및 80%·90%·110% 배율에서 전체 검토·복사 차단.
- QR 통합 테스트: 별도로 기록한 sample_9/11/8 정답 숫자와 `tests/qr-samples.json`의 기존 좌표를 비교합니다. 좌표는 회귀 기준이며 독립적인 픽셀 정답으로 취급하지 않습니다. 과거 Git 커밋 없이도 실행할 수 있습니다.

## 샘플을 통한 지속 개선

`tests/samples.json`에 원본 파일명, 별도 확인한 정답 숫자·좌표, 허용 좌표 오차를 추가하고 모든 기존 샘플을 다시 검증합니다. 개인정보가 있는 문서 원본과 답안지는 Git에 넣지 않습니다. 로컬 캡처는 `.local-tests/`에만 보관합니다.

`minimumLocated`는 기존 성공 사례를 잃지 않기 위한 하한입니다. 이 하한을 통과해도 미검출은 보고서에서 실패로 집계됩니다. 알려진 미검출을 정답에서 삭제하거나 기대값을 자동 결과로 덮어쓰지 않습니다. 이후에는 별도의 미사용 평가 문서도 누적해 과적합을 확인해야 합니다.

이 프로그램은 샘플 업로드만으로 자동 학습하거나 모델을 갱신하지 않습니다. 정답 확인, 알고리즘 수정, 전체 회귀 검증을 거쳐 개선을 축적합니다.
